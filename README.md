# Contract Compliance Review System
**UoA MAI Hackathon 2026 — Team 04**

An AI-powered contract compliance review tool built on Azure AI Foundry and local RAG. The system reviews contract clauses against the University of Auckland's contracting position document and flags issues for manager intervention.

---

## How It Works

1. User uploads a contract (PDF or Word)
2. The system identifies the contract type and asks for confirmation
3. Each clause is reviewed against the UoA position document
4. A colour-coded Word report is generated with reasoning and manager alerts

### Clause Status Codes

| Status | Meaning |
|---|---|
| 🟢 GREEN | Fully compliant with position document |
| 🔴 RED | Violates a position requirement — manager alert |
| 🔵 BLUE | No matching position clause found — manager alert |
| 🟡 AMBER | Uncertain — historical records checked + manager alert |

### Supported Contract Types

- Public Research Contracts
- Commercial Research Contracts
- Subcontracts
- Material Transfer Agreements
- Data Transfer Agreements
- Collaboration Agreements
- Confidential Disclosure Agreements

## Setup (Run Once)

Download documents from Azure Blob Storage and build the local vector store:

```bash
python setup_rag.py
```

This will:
- Download the position document, contract templates, and historical contracts from Azure Blob Storage
- Parse all documents (with OCR for scanned pages)
- Build a FAISS vector store saved to `vector_store/`

This step only needs to be run once, or again if the source documents are updated.

---

## Running a Review

```bash
python generate_report.py path/to/contract.pdf
```

Example:
```bash
python generate_report.py docs/historical/MTA\ example\ 1.pdf
```

The system will:
1. Identify the contract type and ask for confirmation
2. Ask whether to proceed with the review
3. Extract and review all clauses
4. Save a colour-coded Word report to `reports/`

## Architecture

```
Azure Blob Storage (Reader)
    ↓ download once
Local document store (docs/)
    ↓ parse + embed
FAISS vector store (vector_store/)
    ↓ semantic search
Azure OpenAI gpt-4o-mini
    ↓ clause-by-clause judgement
Word report (reports/)
```

### Key design decisions

- **Local RAG instead of Azure AI Search** — the Azure subscription only grants Blob Reader access, so documents are downloaded once and indexed locally with FAISS
- **OCR fallback** — scanned PDF pages are processed with Tesseract when text extraction yields fewer than 50 characters
- **Retry logic** — all LLM calls retry up to 3 times on JSON parse failure; Azure content filter errors skip retries immediately
- **Human confirmation** — contract type is identified by the model but must be confirmed by the user before review begins

---

## Notes

- The vector store does **not** need to be rebuilt between reviews — only rebuild if source documents change
- Azure's content filter may flag certain medical or research-related clauses; these are automatically marked AMBER for manual review
- Reports are saved with a timestamp in the filename to avoid overwriting previous reviews
